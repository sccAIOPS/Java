# 📖 Glossary

> Definitions of key terms used throughout the documentation

---

## A

**Adaptive Algorithm**: An algorithm that changes its behavior based on information gathered during execution.

**Amortized Analysis**: A method of analyzing algorithm time complexity that averages the time over a sequence of operations.

**Asymptotic Analysis**: The study of algorithm performance as input size approaches infinity.

## B

**Big-O Notation**: Upper bound on algorithm growth rate. f(n) = O(g(n)) means f grows no faster than g.

**Big-Ω (Omega)**: Lower bound on algorithm growth rate.

**Big-Θ (Theta)**: Tight bound (both upper and lower) on growth rate.

**Balanced Tree**: A tree where the heights of subtrees are controlled to ensure O(log n) operations.

## C

**Cache-Friendly**: An algorithm that takes advantage of CPU cache by accessing memory in patterns that minimize cache misses.

**Complete Binary Tree**: A binary tree where all levels are fully filled except possibly the last.

**Comparison Sort**: A sorting algorithm that only uses comparisons between elements.

## D

**DAG**: Directed Acyclic Graph - a directed graph with no cycles.

**Divide and Conquer**: Algorithm paradigm that breaks problems into smaller subproblems.

**Dynamic Programming**: Algorithm paradigm that stores subproblem solutions to avoid recomputation.

## E

**Edge**: A connection between two vertices in a graph.

**External Sorting**: Sorting algorithms designed for data that doesn't fit in memory.

## G

**Greedy Algorithm**: An algorithm that makes locally optimal choices at each step.

**Graph**: A data structure consisting of vertices and edges.

## H

**Hash Function**: A function that maps data to a fixed-size value.

**Heap**: A tree-based data structure satisfying the heap property.

**Heuristic**: A practical method that may not be optimal but is sufficient for the purpose.

## I

**In-place Algorithm**: An algorithm that uses O(1) extra space.

**Invariant**: A condition that remains true throughout algorithm execution.

## L

**Lower Bound**: The minimum number of operations required by any algorithm solving a problem.

## M

**Memoization**: Caching results of expensive function calls for reuse.

**MST (Minimum Spanning Tree)**: A tree that connects all vertices with minimum total edge weight.

## N

**NP-Complete**: A class of problems that are both NP and NP-Hard.

## O

**Optimal Substructure**: When optimal solution contains optimal solutions to subproblems.

**Overlapping Subproblems**: When the same subproblem is solved multiple times.

## P

**Polynomial Time**: Algorithm with time complexity O(n^k) for some constant k.

**Pruning**: Eliminating branches in a search tree that cannot lead to a solution.

## R

**Recurrence Relation**: An equation that defines a sequence based on previous terms.

**Recursion**: A method where the solution depends on solutions to smaller instances.

## S

**Stable Sort**: A sort that preserves the relative order of equal elements.

**Space Complexity**: The amount of memory an algorithm uses.

**Spanning Tree**: A subgraph that includes all vertices and is a tree.

## T

**Time Complexity**: The computational time an algorithm requires as a function of input size.

**Topological Sort**: Linear ordering of vertices in a DAG.

## V

**Vertex**: A node in a graph.

## W

**Worst Case**: The input that causes the maximum number of operations.
